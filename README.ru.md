# RAM Limiter

Русская версия | [English](README.md)

Легковесная утилита для Windows, которая снижает потребление оперативной памяти любым приложением путём периодической очистки рабочего набора памяти. Написана на Rust для минимального потребления ресурсов.

![License](https://img.shields.io/badge/license-MIT-blue.svg)
![Platform](https://img.shields.io/badge/platform-Windows-blue.svg)

## 📋 Обзор

RAM Limiter помогает управлять использованием памяти в Windows, автоматически вызывая `SetProcessWorkingSetSize` для выбранных приложений. Это заставляет Windows очищать рабочий набор целевых процессов, перемещая неиспользуемые страницы памяти на диск и освобождая физическую оперативную память.

**Сценарии использования:**
- Снижение потребления RAM у прожорливых приложений (Браузеры, Discord, Музыка)
- Одновременная работа большего количества приложений на системах с ограниченной памятью
- Предотвращение утечек памяти, потребляющих всю доступную RAM
- Оптимизация производительности на системах с малым объёмом памяти

## ⚠️ Отказ от ответственности

**ВАЖНО:** Приложения, подвергнутые воздействию RAM Limiter, могут работать нестабильно или испытывать снижение производительности. Этот инструмент принудительно очищает память процессов, что может вызвать:

- Увеличение операций ввода-вывода на диск из-за свопинга памяти
- Временные зависания или подтормаживания при повторном обращении к очищенной памяти
- Потенциальные сбои в приложениях, которые плохо справляются с нехваткой памяти
- Снижение производительности в задачах, интенсивно использующих память

## ✨ Возможности

- **Простой GUI** — Добавляйте приложения через выбор .exe файлов или из списка запущенных процессов
- **Визуальная обратная связь** — Отображение использования RAM отслеживаемыми приложениями в реальном времени
- **Управление для каждого приложения** — Включение/отключение ограничения для каждого приложения индивидуально
- **Настраиваемый интервал очистки** — Управляйте частотой работы воркера (100 мс – 600 000 мс)
- **Главный выключатель** — Поставьте всё ограничение на паузу одной галочкой, не трогая отдельные приложения
- **Пропуск окна в фокусе** — Не трогать процесс активного окна, чтобы не было подтормаживаний
- **Режим мягкого лимита** — При желании задайте конкретный потолок рабочего набора (например, 500 МБ) вместо очистки до минимума
- **Триггер-процессы** — Ограничивать только тогда, когда работает один из «важных» процессов
- **Статистика page faults и записи на диск** — Кумулятивный счётчик промахов страниц и оценка байтов, отправленных в файл подкачки
- **Профили / пресеты** — Сохраняйте и загружайте именованные конфигурации под разные сценарии (игры, простой, работа, …)
- **Извлечение иконок** — Автоматическое отображение иконок приложений в списке
- **Автозапуск** — Опциональная интеграция с автозагрузкой Windows (запуск свёрнутым в трей)
- **Сохранение настроек** — Конфигурация сохраняется в `%APPDATA%\RamLimiter\config.json`
- **Крайне легковесная** — Потребляет всего ~2 МБ оперативной памяти, размер исполняемого файла ~0.5 МБ

> **Примечание об интерфейсе:** Интерфейс намеренно минималистичен и построен на нативных Win32 элементах управления для максимальной производительности и минимального потребления ресурсов. Акцент сделан на функциональности и эффективности, а не на визуальной эстетике.

## 🚀 Установка

### Готовый бинарный файл

1. Скачайте последний релиз со страницы [Releases](../../releases)
2. Распакуйте `ram-limiter.exe` в любую папку
3. Запустите `ram-limiter.exe`

### Сборка из исходников

**Требования:**
- Rust 1.70+ (установите с [rustup.rs](https://rustup.rs))
- Windows 10/11

**Шаги:**
```sh
git clone https://github.com/yourusername/universal-ram-limiter.git
cd universal-ram-limiter
cargo build --release
```

Скомпилированный бинарный файл будет находиться в `target/release/ram-limiter.exe`.

## 📖 Использование

### Добавление приложений

1. **Выбор исполняемого файла:**
   - Нажмите "Browse .exe…"
   - Выберите .exe файл приложения
   - Приложение будет добавлено в список с его иконкой

2. **Выбор из запущенных процессов:**
   - Нажмите "Pick running process…"
   - Выберите процесс из списка (отсортирован по использованию RAM)
   - Нажмите "Add Selected"

### Управление приложениями

- **Включить/Отключить:** Дважды кликните на приложение в списке для переключения ограничения
- **Настроить / удалить:** ПКМ по строке — контекстное меню (переключить, задать/сбросить мягкий лимит, удалить)
- **Просмотр использования RAM:** Колонка "RAM" показывает текущий рабочий набор приложения
- **Счётчик page faults:** Колонка "Page faults" — кумулятивное число промахов страниц для приложения

### Главный выключатель и общие настройки

В верхней панели находятся настройки уровня всего лимитера:

- **Master enabled** — Если выключено, никакая очистка/кап не выполняется, что бы ни говорили отдельные приложения. Строка статуса покажет `master switch OFF`.
- **Skip focused** — Если включено, лимитер не трогает процесс активного окна, чтобы не было подтормаживаний при работе.
- **Interval (ms)** — Как часто срабатывает воркер. Меньше = агрессивнее очистка и больше нагрузка на диск, больше = мягче. Диапазон: 100 мс – 600 000 мс (10 минут).
- **Triggers** — Список процессов через запятую (например, `chrome, discord`). Если не пусто, лимитер работает только пока запущен хотя бы один из этих процессов. Пусто — всегда включён.

### Режим мягкого лимита

По умолчанию лимитер очищает рабочий набор до минимума, и Windows вытесняет большинство страниц в файл подкачки. Для некоторых приложений это слишком агрессивно. ПКМ по строке → **Set soft limit…**, введите значение в МБ — лимитер будет держать рабочий набор не выше этого предела (страницы выше предела вытесняются, страницы ниже остаются в RAM). **Clear soft limit** возвращает обычный режим очистки.

### Профили

Кнопка **Profiles…** открывает менеджер профилей. Профиль — это полный снимок настроек: список приложений плюс мастер-выключатель, skip-focused, интервал и триггеры. Примеры:

- "Gaming" — только Chrome, Discord, Spotify включены, интервал 1.5 с, триггер `<имя_игры>.exe`.
- "Office" — мягкий лимит 800 МБ для Outlook, мастер включён, skip focused.
- "Idle" — мастер включён, без триггеров, интервал 10 с, очищаем всё.

Активируйте профиль для загрузки. Сохраняйте текущие настройки в новый профиль из того же окна. Удаление лишь убирает сохранённый снимок — текущие настройки не меняются.

### Живая статистика

Под списком приложений:

- **Status line** — суммарная RAM по отслеживаемым процессам, сколько активны, состояние мастер-выключателя.
- **Stats line** — `Trimmed: <N MB>` это оценка байтов, которые лимитер вытолкнул в файл подкачки (сумма падений рабочего набора по всем циклам); `Page faults: <N>` это кумулятивное число промахов страниц по всем отслеживаемым процессам.

### Автозапуск

Отметьте "Start with Windows" для автоматического запуска RAM Limiter при входе в систему. Приложение будет запускаться свёрнутым в системный трей.

### Как это работает

RAM Limiter запускает фоновый поток, который:
1. Перечисляет все запущенные процессы один раз за **интервал очистки** (настраиваемый, по умолчанию 1.5 с).
2. Для каждого включённого приложения:
   - Если задан **мягкий лимит**, вызывает `SetProcessWorkingSetSizeEx(handle, 1 МиБ, soft_limit, 0)` — ОС держит рабочий набор не выше cap.
   - Иначе вызывает `SetProcessWorkingSetSizeEx(handle, -1, -1, 0)` — Windows очищает рабочий набор до минимума.
3. Windows перемещает соответствующие страницы в файл подкачки, освобождая физическую RAM.
4. Воркер также читает `PROCESS_MEMORY_COUNTERS`, чтобы наполнять статистику page faults и оценку записи на диск в UI.

Воркер уважает:
- **Мастер-выключатель** (если выключен — вообще ничего не делается).
- **Триггеры** (если заданы — лимитер работает только пока запущен один из триггер-процессов).
- **Skip focused** (процесс активного окна не трогается, даже если он подпадает под ограничение).

## 🛠️ Технические детали

### Архитектура

- **Язык:** Rust (редакция 2021)
- **GUI фреймворк:** [native-windows-gui](https://github.com/gabdube/native-windows-gui)
- **Windows API:** Прямые вызовы WinAPI через [winapi-rs](https://github.com/retep998/winapi-rs)

### Ключевые компоненты

- `src/main.rs` — Точка входа, обработка флага `--minimized`
- `src/ui.rs` — Реализация GUI (окно, список, диалоги)
- `src/limiter.rs` — Фоновый рабочий поток, перечисление процессов, очистка памяти
- `src/config.rs` — Сохранение конфигурации, управление автозапуском через реестр
- `src/icon_extract.rs` — Извлечение иконок из .exe файлов с помощью `ExtractIconExW`

### Очистка памяти

В режиме обычной очистки используется:
```rust
SetProcessWorkingSetSizeEx(handle, usize::MAX, usize::MAX, 0);
```

В режиме мягкого лимита используется:
```rust
// soft_limit_bytes = soft_limit_mb * 1024 * 1024 (минимум 2 МиБ)
SetProcessWorkingSetSizeEx(handle, 1 * 1024 * 1024, soft_limit_bytes, 0);
```

Оба варианта — легитимные вызовы Windows API. Хотя это эффективно освобождает RAM, агрессивное использование может повлиять на производительность приложений.

## 🔒 Безопасность и конфиденциальность

- **Без сетевого доступа** — Все операции выполняются локально
- **Минимальные разрешения** — Требуются только `PROCESS_QUERY_INFORMATION` и `PROCESS_SET_QUOTA`

## 📝 Конфигурация

Настройки хранятся в формате JSON по адресу:
```
%APPDATA%\RamLimiter\config.json
```

Пример:
```json
{
  "apps": {
    "C:\\Program Files\\App\\app.exe": {
      "exe_path": "C:\\Program Files\\App\\app.exe",
      "display_name": "Моё приложение",
      "enabled": true,
      "soft_limit_mb": 500
    }
  },
  "autostart": false,
  "trim_interval_ms": 1500,
  "global_enabled": true,
  "skip_focused": true,
  "triggers": ["chrome", "discord"],
  "active_profile": "Gaming",
  "profiles": {
    "Gaming": {
      "apps": { "...": "..." },
      "trim_interval_ms": 1500,
      "global_enabled": true,
      "skip_focused": true,
      "triggers": ["yourgame"]
    },
    "Idle": {
      "apps": { "...": "..." },
      "trim_interval_ms": 10000,
      "global_enabled": true,
      "skip_focused": false,
      "triggers": []
    }
  }
}
```

Все новые поля верхнего уровня необязательные и подставляют разумные значения по умолчанию, поэтому конфиги от старых версий продолжают работать.

## 🐛 Устранение неполадок

**Приложение вылетает после включения ограничителя:**
- Отключите ограничение для этого приложения
- Некоторые приложения плохо справляются с агрессивной очисткой памяти
- Попробуйте ограничивать реже, изменив длительность сна в `limiter.rs`

**Ошибки "Доступ запрещён":**
- Некоторые системные процессы защищены и не могут быть ограничены
- Запустите RAM Limiter от имени администратора (не рекомендуется по соображениям безопасности)

**Высокая нагрузка на диск:**
- Это ожидаемое поведение — очищенная память перемещается в файл подкачки
- Уменьшите количество ограничиваемых приложений или отключите ограничение для дисково-интенсивных приложений

**⚠️ ВНИМАНИЕ: Износ диска**

Агрессивная очистка памяти может значительно увеличить износ диска, особенно SSD:

- **Усиление записи:** Каждые 1.5 секунды Windows может записывать сотни МБ в файл подкачки
- **Оценка износа:** 30-300 ГБ записи в день на каждое ограничиваемое приложение (в зависимости от паттернов использования)
- **Влияние на срок службы SSD:** Может сократить срок службы SSD на месяцы или годы при постоянном использовании
- **Влияние на HDD:** Повышенный механический износ, шум и снижение производительности из-за постоянного движения головок

**Рекомендации для минимизации износа диска:**
- Ограничивайте приложения только когда RAM критически мало (< 20% свободной)
- Предпочитайте ограничение фоновых/неактивных приложений, а не активно используемых
- Рассмотрите увеличение интервала очистки в `limiter.rs` с 1.5с до 5-10с
- Мониторьте статистику записи на диск с помощью инструментов типа CrystalDiskInfo
- Избегайте ограничения приложений на системах с достаточным объёмом RAM (16+ ГБ)

**Иконки не отображаются:**
- Некоторые исполняемые файлы не содержат встроенных иконок
- Приложение всё равно будет работать, просто без визуальной иконки
